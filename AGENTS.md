# Planici - agent guide

Scheduling & business management for independent professionals. Turborepo + pnpm monorepo.
Product docs are in Portuguese; code, commits and agent files are in English.

## Context rules (the important parts)

1. **Cards before sources.** Before reading code outside your domain, read the owning card in `.ai/context/`.
2. **Don't explore other domains.** If the card is missing, stale, or doesn't answer you, stop and end your reply with a `NEEDS` block (see `.ai/README.md`). The orchestrator routes it to the owner.
3. **One writer per path.** Only the owner edits files in its domain. Everything else is a request.
4. **Return summaries, not dumps.** Report <= 40 lines: what changes, files touched, open questions.
5. **Per-task handoffs** go to `.ai/work/<TICKET-ID>/` (gitignored). Durable knowledge goes to the cards.

## Orchestration
For a Linear ticket or any change touching 2+ domains, the main session is the orchestrator:
follow `.agents/skills/feature-pipeline/SKILL.md`. It delegates in waves
(spec + design -> contracts + db -> api + web + platform -> quality-gate) and never reads app source itself.
Small single-domain edits don't need the pipeline.
No tickets yet? Use `.agents/skills/plan-backlog/` to turn the RFC into Linear issues.

Agent definitions: Claude Code `.claude/agents/*.md` (source of truth) -> Codex `.codex/agents/*.toml`
(generated by `node scripts/ai/sync-codex-agents.mjs`). Skills: `.agents/skills/` (symlinked as `.claude/skills`).

## Commands

```bash
pnpm install
pnpm lint && pnpm typecheck && pnpm test # whole repo (turbo)
pnpm --filter api test # api unit (vitest)
pnpm --filter api test:e2e # api e2e (Testcontainers -> needs Docker)
pnpm --filter @planici/schemas build # required before api/web typecheck after contract changes
pnpm --filter web lint:fix
```

Lint: Biome (root, web, packages) and oxlint + prettier (api). Husky runs lint-staged + tests on commit

## Non-negotiables

- Request/response shapes live **only** in `packages/schemas`; api and web import them.
- API features follow the existing slice: `modules/<ctx>/<name>/{command,handler,http.controller,handler.spec}.ts`.
- Never hand-edit `apps/api/drizzle/meta/**` or `pnpm-lock.yaml`.
- Never commit secrets; `.env` files are local only.
- Multi-tenant: every tenant-scoped table/query carries `tenant_id` (RFC §5, §6).
